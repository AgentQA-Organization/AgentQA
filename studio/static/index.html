How to write requirements for a test

The agent reads your source with CodeGraph and drives the real app before it asks you anything — so it already knows the screens, the buttons, the navigation and the API calls. What it cannot know is what should count as passing. Write that.

1
When does this test PASS?

The observable end state, not the steps. "The home tab bar is visible after signing in." Everything downstream — the assertion, the edge cases — comes from this one sentence.

2
When does it FAIL?

What a real failure looks like. "An inline error under the password field; stays on the login screen." This is what stops a failing test from later being "fixed" by loosening its assertion.

3
What could BLOCK it?

Things that stop the run without the feature being broken: OTP/2FA, a permission prompt, a paywall, required test data or backend state, a feature flag.

4
Which ENTRY POINT?

Only when the flow is reachable from several places (welcome screen, account tab, a 401 bounce). Name the one the test should use.

Worth writing
  • The success criterion, in one sentence
  • What a real failure looks like
  • Blockers, test accounts, required backend state
  • Which environment (staging / production / mock)
  • Edge cases you actually care about
Skip it — the agent finds this itself
  • Where the buttons are, what the screens contain
  • Step-by-step tap instructions
  • Which APIs get called, what validations exist
  • How navigation works
Template — save as .md and attach it
# Sign in with a valid account

## Success
The home tab bar is visible after signing in.

## Failure
An inline error appears under the password field and the app stays on the login screen.

## Blockers
- OTP / 2FA: none on staging accounts
- Permission prompts: notifications prompt on first launch — dismiss it
- Test data: account in MYTV_USERNAME / MYTV_PASSWORD (env var names only, never the values)
- Backend: staging must be up; a 404 dialog means the environment is down, not a test failure

## Entry point
Cold launch to the welcome screen (not the account tab).

## Environment
staging, clean install (app data reset before the run)

## Edge cases worth covering
- wrong password
- empty password

A requirements file is treated as intent, not truth: the agent still confirms each point with you on the Clarify card, and where the live app disagrees with the document, the live app wins and it tells you about the difference.
